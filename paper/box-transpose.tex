\begin{abstract}
Changing the order of a tensor's axes in PyTorch is free. Fixing the layout
afterwards is not. \texttt{.contiguous()} makes a copy, so peak memory doubles.
On a machine that is almost full, the job fails there.

We present \emph{box transpose}. It fixes the layout in place. We break the
permutation into swaps of neighbouring groups of axes. Each swap is a matrix
transpose. We carry it out by walking its cycles, holding one value in a
register.

Some cells are already in the right place. A copy still has to write them. We
skip them. So box transpose can move only \emph{part} of the tensor, where
every earlier method has to go over all of it. How large that part is comes
from the shape in one line of arithmetic. So the method predicts its own
speedup before touching any data, using no number measured on a GPU.

We tested \resCases{} shapes at ranks \resRankLo{} to \resRankHi{}. Our method
used \resBoxAux{} bytes against a \resTensorMB{}\,MB tensor. It beat three
published in-place methods on \resWinIttpd{}, \resWinGl{} and \resWinGv{} of
their cases. When the permutation leaves a large group of axes at the back
alone, and the swap is one small square, it is \tierBeatsX{}$\times$ faster
than \texttt{.contiguous()} itself. When no group survives at the back, it is
the slowest method we measured. We say exactly where that line is.
\end{abstract}
