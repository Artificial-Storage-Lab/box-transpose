\subsection{Planning by shortest path}
\label{sec:planning}

A permutation can always be reached by bubbling each axis into position with
single-axis swaps. Treating a run of adjacent axes as one box instead turns
the decomposition into a shortest-path problem over axis orderings, and the
search is free to spend one swap where the baseline spends several.

To measure what that freedom is worth we plan every permutation of a tensor of
\planElements{} elements at each rank from \planRankLo{} to \planRankHi{} ---
\planRanks{} shapes, \planCases{} permutations, each planned by both
strategies for \planPlans{} plans in all. The comparison is paired: both
planners see the same shape and the same permutation, and every rank holds the
element count fixed, so a difference in bytes moved is a difference in the
decomposition rather than in the tensor.

Across the sweep the search issues \planStepFactor{}x fewer swaps than the
adjacent baseline and moves \planByteFactor{}x fewer bytes at the median,
reaching \planByteFactorMax{}x on the permutation where it helps most. The
margin widens with rank, as Figure~\ref{fig:steps} shows: at rank
\planRankHi{} the median permutation costs the baseline
\planStepsBaselineTop{} swaps and the search \planStepsSearchTop{}.
Table~\ref{tab:planners} gives the breakdown. \planBlockShare{}\% of the
swaps the search selects bundle more than one axis into a box, which is the
move the baseline cannot make and where the difference comes from.

The auxiliary cost of a plan is its cycle metadata, and it does not scale with
the tensor: the largest plan in the sweep needs \planAuxWorst{} bytes, or
\planAuxPercent{}\% of the data it permutes. The data itself is never copied
to a second buffer.

\subsection{Cost model}
\label{sec:cost}

Edge weight is bytes moved divided by a calibrated throughput $\mu$, currently
\costMu{}~GB/s. Two thresholds gate the search: $\tau$, the smallest $D_{post}$
at which an edge is worth considering, and $D_{post}^{*}$, the point at which
box following beats a cycle splitter. Both currently sit at \costTau{} and
\costDPostStar{}, so the pruning they describe is \costPruning{}.
