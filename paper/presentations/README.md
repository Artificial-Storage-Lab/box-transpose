# presentations

`proposal.pptx` is the proposal presentation. Upload it to Google Slides with
**File > Import slides**, or drop it in Drive and open it with Slides.

```bash
make deck        # from the repo root, or from paper/
```

## What is on it

Nine slides, one per graded component of `../proposal_guidelines.pdf`, plus a
title slide. Everything on them is already in `box-transpose.pdf`. Nothing is
added for the deck, because a slide that says something the paper does not is
a slide that can go stale on its own.

## No number here is typed

`build_deck.py` reads the same `sections/*/_generated/*.defs.tex` macros the
paper's prose cites, and the same `raw_data/` rows the paper's table is built
from, through the same helpers in `../pipeline/`. The milestone slide reads
`SCHEDULE` straight out of `../pipeline/tables/gen_table_timeline.py`, so the
deck and the paper's Table 2 cannot disagree.

Re-run the experiment, then `make deck`, and the slides move with the paper.

## Files

```
build_deck.py        builds proposal.pptx
render_equation.py   typesets Equation (1) to a PNG, using the paper's LaTeX
preview_deck.py      draws each slide as a PNG, for layout review
equation-shapes.png  generated by render_equation.py
proposal.pptx        the deliverable
preview/             generated by preview_deck.py, gitignored
```

## Checking the layout

There is no PowerPoint and no LibreOffice in this container, so the usual
"convert to PDF and look at it" pass is not available. `preview_deck.py` reads
the shapes back out of the `.pptx` and draws them at their real positions and
sizes:

```bash
python3 preview_deck.py            # writes preview/slide-N.png
python3 preview_deck.py --check    # exits 1 on overflow or margin problems
```

It is an approximation, not a renderer. It uses DejaVu rather than
Calibri/Cambria, and DejaVu is the wider of the two, so **text that fits in the
preview fits in PowerPoint**; text that overflows the preview may still be
fine. `make deck` runs the `--check` pass, so a layout regression fails the
build.

That said, the preview cannot tell you how Google Slides will render the
fonts. Look at the deck once after uploading it.
